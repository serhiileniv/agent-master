How it works

Point it at a project folder and add agents. Each gets a real terminal, a branch, and a checkout of its own — so they work at once without seeing each other's edits, or yours.

A branch and a worktree each

Every agent gets a private checkout, so parallel edits can't collide. Agents are pinned to their worktree after spawn — even a shell profile that jumps directories can't walk one into your real tree.

Up to nine live terminals

Real terminals, tiled automatically. Watch them all at once, drag to reorder, and get a desktop ping when a backgrounded agent finishes or needs you.

Several projects, one window

Each project folder becomes a tab with its own canvas of agents. Switch between them without losing anyone's place; the whole tab set returns after a restart.

Merge, apply, or discard

Read an agent's diff against your base branch, then merge it, take only the files you want, or throw the branch away — without leaving the app.

Your working tree is never one of them.

Running several agents on one checkout normally means they overwrite each other's edits, and yours. Agent Master gives each agent its own branch and its own git worktree: a real, separate directory on disk, backed by the same repository.

They live beside your repo, not inside it, so git never reports them as untracked.

When an agent gets it right you review the diff and land it deliberately. Nothing reaches your branch until you say so.

Questions

Does it cost anything to run?

No. Agent Master is MIT-licensed and free, and it has no inference cost of its own — it drives the agent CLIs already installed on your machine, using your existing credentials and plans.

Does my code leave my machine?

Not through Agent Master. There's no account, no telemetry and no background service — it's a desktop app talking to local processes and your local git repo.

The agent CLIs you run inside it are a separate matter: those talk to their own providers exactly as they do when you run them in a terminal yourself.

Do I need a git repository?

No, but it's recommended. Agent Master opens any folder; git is what unlocks per-agent worktree isolation, diff and merge. Without it you still get the parallel terminal stage.

macOS says the app is “damaged and can't be opened.”

Builds aren't yet signed with a paid Apple Developer certificate, so Gatekeeper quarantines them. Remove the quarantine flag once after installing, with the command in the download section above.

Windows shows a comparable one-time SmartScreen prompt (More info → Run anyway). Proper signing and notarization are on the roadmap.

How many agents can run at once?

Up to nine tile automatically on the canvas. Each is a real PTY, so the practical limit is your machine's CPU and memory.

Where does it put things on disk?

Agent worktrees go in an .agentmaster-worktrees folder beside your repo, one directory per agent, on branches named canvas/<id>. Your own checkout is never one of them.

Workspace and layout state lives in a workspaces.json file in the app's user-data folder, written atomically so an interrupted save can't lose your tabs.

What happens to an agent's branch when I'm done with it?

You decide. Merge it into your base branch, apply just the files you want, or discard the branch and its worktree entirely. Nothing is cleaned up behind your back while an agent still has uncommitted work.
